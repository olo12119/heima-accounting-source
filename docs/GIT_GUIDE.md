# Git小白指南：把它当成游戏存档

## Git到底是什么

你可以把整个项目理解成一款正在制作的游戏：

- 项目文件夹是当前正在玩的游戏世界。
- 一次Git提交是一个存档点。
- 七位存档编号类似存档槽编号，例如 `9063717`。
- `main` 是当前主要游玩路线。
- `HEAD -> main` 表示你现在站在主要路线的最新存档上。

Git主要保护程序源码、测试和文档。它不自动保存个人账目数据库、安装包、缓存和整块硬盘，因此不能代替应用内备份或移动硬盘备份。

## 最简单的查看方法

直接双击项目根目录中的：

```text
00-查看Git存档点.cmd
```

窗口会从上到下显示由新到旧的存档。它只读取信息，不会修改任何项目文件。

也可以在项目文件夹中打开PowerShell并输入：

```powershell
git log --oneline --decorate --graph --all
```

如果内容很多并进入翻页界面，按键盘上的 `q` 退出。

## 回档前先分清三种需求

### 1. 只想看看旧存档

这是最安全的做法。它相当于打开旧存档参观，但不改变当前进度。可以查看当时有哪些文件、改了什么，再回到当前版本。

### 2. 想从旧存档另开一条路线

这是推荐的尝试方式。它相当于复制旧存档后另开一个新存档槽，当前 `main` 最新进度仍然保留。确定旧版本更合适后，再决定怎样处理。

### 3. 想让当前版本直接退回旧存档

这种操作可能覆盖现在的文件或丢掉没有存档的修改，风险最高。不要自行执行 `git reset --hard`、强制切换或删除分支。

## 需要回档时怎样告诉Codex

推荐直接这样说：

```text
我要查看存档9063717，但必须保留当前版本。请先解释方案，不要立即回档。
```

或者：

```text
最新修改出现问题，我想撤销它。请先检查有没有未保存内容，列出安全方案让我选择。
```

Codex应该先检查当前文件、解释会发生什么、推荐不破坏现有进度的办法，并在你明确同意后才执行真正的回档。

## 一个重要习惯

每次完成一组能够独立验证的修改，就建立一个说明清楚的新存档点。存档名称应该写出“做了什么”，不能只写“修改”“更新”之类看不懂的文字。以后只需要提供存档编号，就能准确找到当时的版本。
