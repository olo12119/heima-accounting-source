# 黑马记账项目文件地图

这份说明写给不懂编程的项目负责人。你不需要记住所有文件名，也不需要亲自修改程序文件；只要知道哪些是应用本体、哪些是可以重新生成的临时内容、哪些绝对不要随便删除即可。

## 先看最重要的三个入口

1. **想直接打开当前最新版**：双击根目录的 `00-点我打开黑马记账-当前最新版.cmd`。不要进入 `release` 猜测哪个EXE更新。
   - 当前最新版是1.4.0免安装预览版，完整文件位于 `可直接打开-黑马记账-1.4.0预览版`。
   - `release` 中仍是旧1.0.0/1.1.0安装包、单文件便携版和解压目录，不用于检查当前功能。
2. **想学习软件怎样使用**：阅读 [用户指南](USER_GUIDE.md)。
3. **想查看Git存档**：双击 `00-查看Git存档点.cmd`，再阅读 [Git小白指南](GIT_GUIDE.md)。

## 根目录里的文件夹分别是什么

可以把整个项目想成一间制作软件的工作室：`src` 是设计和零件，`tests` 是质检工具，`release` 是已经装箱的成品，其他目录负责说明、构建或存放可重新下载的材料。

| 文件夹 | 通俗解释 | Git 是否保存 | 你是否需要打开 |
| --- | --- | --- | --- |
| `.git` | Git 的“版本保险柜”，保存项目历史。它通常是隐藏文件夹。 | Git 自己管理 | **不要修改或删除** |
| `.cache` | 下载和打包时的本地缓存，减少重复下载。 | 否 | 通常不用打开 |
| `assets` | 应用标识等原始素材。 | 是 | 换品牌素材时才需要 |
| `build` | 制作安装包时使用的图标等资源。 | 是 | 通常不用打开 |
| `docs` | 产品、架构、构建、使用方法和开发过程说明。 | 是 | **适合你查看** |
| `node_modules` | 项目依赖的第三方程序零件，类似装配仓库。 | 否 | 不要手工修改 |
| `out` | 源码经过编译后生成的可运行程序文件。 | 否 | 通常不用打开 |
| `release` | 旧1.0.0/1.1.0安装包、便携版和解压版留档。 | 否 | 当前验收不要使用 |
| `scripts` | 自动生成图标等辅助脚本。 | 是 | 通常不用打开 |
| `src` | 黑马记账真正的程序源码，包括界面、数据库和安全桥接。 | 是 | 开发时最重要，不要随便移动 |
| `test-results` | 自动测试临时留下的结果。 | 否 | 排查测试问题时才需要 |
| `tests` | 自动检查功能是否正常的测试代码。 | 是 | 验收和开发时使用 |

“Git 是否保存”中的“否”不代表这些文件夹没有用，而是它们体积较大、可以重新生成，或者可能包含只属于这台电脑的内容，所以不适合塞进版本历史。

当前还有 `可直接打开-黑马记账-1.4.0预览版` 和上一版1.3.0预览目录。1.4.0才是本轮免安装成品，Git不保存这些大型生成目录。使用时必须保留整个1.4.0目录；真正的启动入口仍是根目录的 `00-点我打开黑马记账-当前最新版.cmd`。

`src/renderer/public/category-3d-atlas.png` 是界面使用的原创3D分类图标图集，属于程序本体并由Git保存，不是可随意清理的图片缓存。

`src/renderer/public/logo-app-v2.png` 是新版AI黑马应用图标的运行时资源，`build/icon.png` 是Windows/macOS构建使用的512像素版本，两者都属于程序本体并由Git保存。

### 由开发工具使用的配置文件

下面这些文件虽然都放在根目录，但不是杂物。开发工具默认会在这里寻找它们，随意移动反而会导致运行、测试或打包失败。

| 文件或文件组 | 通俗解释 |
| --- | --- |
| `package.json` | 项目的“总清单”，记录版本、依赖和可以执行的命令。 |
| `package-lock.json` | 依赖的“精确采购单”，保证不同时间安装到相同版本。 |
| `electron.vite.config.ts` | 规定桌面程序的各部分怎样编译。 |
| `electron-builder.yml` | 规定安装包名称、图标和打包方式。 |
| `tsconfig*.json` | TypeScript 的代码检查规则。 |
| `eslint.config.mjs` | 代码规范检查规则。 |
| `vitest.config.ts`、`vitest.setup.ts` | 单元测试和界面测试配置。 |
| `playwright*.ts` | 模拟真实用户操作的端到端测试配置。 |
| `.gitignore` | 告诉 Git 哪些大文件、临时文件和用户数据不能保存。 |
| `.npmrc` | 让依赖下载缓存优先保存在当前 D 盘项目中。 |
| `*.tsbuildinfo` | TypeScript 为加快检查生成的临时记录，Git 不保存。 |

## 为什么推荐现在不重新整理

当前结构不是把文件随便堆在一起，而是 Electron 桌面应用常见的分工方式。配置文件放在根目录，是因为开发、测试和打包工具会从这里自动寻找；源码、测试和文档也已经分别放入不同文件夹。

如果只为了“看起来文件少”就移动它们，需要同时修改很多路径，可能造成开发命令、测试或安装包失效，却不会给软件功能带来实际提升。因此当前最安全的整理方式，是保留结构并用这份地图帮助理解。

## 哪些内容可以重新生成

以下内容在确认用途后可以清理，但每次清理前仍应先检查并说明影响：

- `out`、`test-results` 和 `*.tsbuildinfo`：可以通过重新构建或测试生成。
- `release`：可以重新打包生成，但删除前应先确认安装包已经另外保存，重新打包也需要时间。
- `node_modules`：可以通过 `npm install` 重新下载，但体积大，下载需要网络和时间。
- `.cache`：可以重新下载或生成，但会让下一次安装依赖、制作安装包变慢。

以下内容不能因为“文件多”就清理：

- `.git`、`src`、`tests`、`docs`、`assets`、`build`、`scripts`。
- 根目录的 `package.json`、`package-lock.json`、各类配置文件、`README.md` 和 `AGENTS.md`。

## 项目文件与个人账目不是同一回事

Git 保护的是项目源码和文档，不保存你在黑马记账中录入的个人账目。Windows 上的账目数据库位于：

```text
%APPDATA%\HeimaAccounting\data\heima-accounting.sqlite3
```

不要在应用运行时手工改动数据库。保护账目应使用应用内的“完整备份”功能，并把备份文件复制到另一个安全位置。也就是说：

- 防止程序代码和功能误改：依靠 Git。
- 防止个人账目丢失：依靠应用内完整备份。

## 以后需要整理时怎样做

你只需要告诉 Codex“检查哪些文件可以安全清理”。Codex 应先说明每个目标是什么、删除后有什么影响、能否恢复，并在你同意后再操作。不要直接用清理软件或批量删除项目文件夹。
