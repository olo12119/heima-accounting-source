# 黑马记账技术决策

## Android唯一移动目标与工程分离

用户的主力设备是Android手机，因此下一阶段只制作Android应用，不制作iOS版。iCost、Apple原生应用、visionOS和Liquid Glass只作为信息层级、材质和动效的参考，交互必须遵守Android返回手势、字体缩放、权限和性能规则。

正式Android实现推荐 **Kotlin + Jetpack Compose**。Kotlin是Android官方主流开发语言，Compose是现代原生界面工具；对用户来说，它像“按Android的原生规格造房子”，比继续套用Electron更适合手机手势、系统后台、生物识别和不同Android机型。没有选Flutter，是因为已明确不制作iOS，不再需要为一套代码跨两个手机系统付出额外的框架成本。

总项目使用“一个Git存档库、两个独立App”的结构：Windows Electron工程位于 `apps/windows-desktop`，Android原生工程位于 `apps/android`，设计资产位于 `design/android`，共用备份协议预留在 `shared/contracts`。这样Windows不会污染Android构建，又能让两者共用Git存档和受控的数据迁移规则。

为避免过早编码把错误界面固化，阶段顺序固定为：完整UI Design Document → 高保真交互原型 → 用户逐页确认 → Android正式编码。前三步已经完成，并已根据第一轮真机反馈交付 `0.2.0-visual` 可安装视觉修正版APK；该版本只用于手机检查布局、主题、材质和动效，不含正式数据持久化。

Android工程使用AGP 9.3.1、Gradle Wrapper 9.7.1、Kotlin Compose编译器2.4.10和Compose BOM 2026.08.00。最低Android 10（API 29），目标和编译标准为Android 17（API 37），JDK固定为17。工具链使用项目Wrapper与D盘缓存，不依赖Android Studio或系统PATH。

Liquid Glass不是主题名称，也不采用全屏实时模糊。`0.2.0-visual` 使用Haze 1.7.2在Android 12及以上为局部重点表面提供真实背景采样，并用半透明渐变、细边框、高光、噪点和短时阴影表达厚度；旧系统、省电模式或降低视觉质量时回退到更实的半透明表面。页面切换只使用位移、透明度和缩放。真实帧率、发热和Batterystats必须等用户手机临时USB调试后测量，电脑编译不能替代。

项目路径保留中文和空格。APK打包可在原路径完成，但Gradle单元测试运行器复用中文绝对路径时无法加载测试类，因此一键脚本临时把同一目录映射为 `H:` 并关闭该次配置缓存。脚本用专用标记验证盘符指向正确项目，结束后删除自己创建的映射；这不是移动或复制工程。

## 小范围自用的功能取舍

产品供用户本人和周边人使用，不需要用大众互联网产品的功能数量证明完整度。保留能直接减少漏记、重复劳动和数据丢失的本地能力：搜索与日历、预算、手动确认的周期模板、CSV导入、备份恢复、退款/报销和隐私密码。暂不建设银行直连、账号云服务、多人共享、投资行情、OCR/AI、多币种、企业审批和自动更新服务。Android移动端现已转为下一阶段主要目标，不再属于排除项。

这个选择减少了第三方账号、服务器费用、隐私合规、同步冲突与长期运维，不影响个人账本的核心价值。将来只有真实使用频繁遇到某个问题时，才重新评估对应功能。

## 退款、报销与统计口径

普通收入是真正增加可支配资金的收入；退款和报销是之前支出的返还。后两者必须关联一笔原支出，并在支出统计和原分类中抵扣，不能放进工资等收入排行，否则会同时夸大收入和支出。另设“排除统计”标记用于内部转账等只需留档的特殊记录。

## 预算与周期模板

预算采用月度总额加一级支出分类额度，定位是提醒而不是强制拦截。周期账单采用“到期提醒、用户点击后生成”，不在后台自动入账，避免用户没有实际支付却出现虚假账目。模板和预算均保存在SQLite并进入完整备份。

## 本机隐私密码

密码只用于防止身边的人随手打开。数据库保存随机盐和 `scrypt` 派生校验值，不保存明文；每次App重新启动都回到锁定状态。没有把它宣传为数据库加密，因为拥有电脑文件和专业工具的人仍可能直接读取SQLite。真正的静态文件保护应依赖Windows账户与磁盘加密。

## 自定义分类的权限边界

系统预设分类作为稳定基础保持锁定，用户只能读取和使用；用户可以创建自己的一级分类，也可以在系统或自定义一级分类下扩展二级分类。自定义分类没有账目引用时可以删除，有引用时只能停用。这样既满足个性化，又避免外键断裂导致历史账目无法显示。

分类继续保存在SQLite的 `categories` 表中，通过 `is_system` 和 `is_active` 区分系统、自定义、启用与停用状态。所有新增、编辑、排序、停用和删除请求都经过受限preload、IPC来源检查和Zod校验，数据库层再次拒绝对系统分类的修改。

## 分类图标与颜色主题

- 28个常用分类图标升级为一张原创黏土质感3D透明图集，界面通过固定7×4坐标裁切，避免为每个分类请求外部图片；旧的Phosphor `duotone` 图标作为未覆盖自定义图标的可靠后备。分类之外的普通操作按钮继续使用Lucide。
- 自定义分类只能从审核过的图标和低饱和颜色列表中选择，避免任意字符串、不可读颜色或外部图片进入数据库。
- 明暗方式和心情主题分开保存。`theme` 负责浅色、深色或跟随系统，`color_theme` 负责黑马经典、暖阳活力、云朵治愈或保留的深海专注，因此不用维护十二套互相重复的完整主题。
- 三套主要心情主题共享操作位置，但会共同改变背景、主色、卡片圆角、阴影和首页图表舱；顶栏只展示三套日常主题，完整设置继续提供深海专注，避免升级时删除用户原有选择。
- 老数据库没有 `color_theme` 时默认使用内部编号 `forest`（当前界面名称“黑马经典”），不会在升级后突然改变外观。

## 品牌图标、动效与手机准备

- 应用图标使用内置AI绘图能力生成，不照搬第三方品牌素材。1.5.0按照用户偏好改为白瓷圆角底、黑马侧脸和克制的鎏金图表徽章；固定图标不跟随心情主题变化，保证Windows快捷方式始终容易识别。
- 复杂动效使用 `motion`，因为它能可靠处理弹性弹窗、布局补位、共享导航高亮和数值变化；普通悬停与环境光继续使用CSS，图表继续使用Recharts自带动画，避免所有动作都依赖一个库。
- 动画只改变透明度、位移、缩放和旋转等适合GPU合成的属性，并支持 `prefers-reduced-motion`。不采用持续粒子和大幅3D翻转，避免旧电脑掉帧和长期使用疲劳。
- 最初尝试“旧页退出完毕后新页进入”的串行页面动画，自动逐页截图发现连续切换可能停在空白内容区。最终改为新页立即分层进入，保留动感并消除等待状态竞争。
- Electron程序不能直接完美兼容手机。当前继续验证Windows体验，同时把860像素以下改成底部导航、单列卡片和悬浮记账按钮。未来移动端可复用React页面、类型和业务逻辑，但SQLite、文件备份、窗口与安全桥接必须使用手机平台实现。

## 收入与支出共用账目模型

收入和支出拥有相同的金额、日期、备注与两级分类结构，因此继续使用同一张账目表，并增加受约束的 `entry_type` 字段，而不是复制两套表和接口。分类同样标记适用类型，主进程会校验“账目类型、一级分类、二级分类”三者一致。这样可以统一编辑、导出和备份，也能在首页可靠计算收入减支出的结余。数据库第2版迁移将旧数据明确标记为支出，避免破坏现有账本。

## 1. 桌面框架

| 方案 | 优点 | 缺点 | 本机落地情况 |
| --- | --- | --- | --- |
| Tauri 2 | 体积小、内存较低、系统 WebView | 需要 Rust、Cargo、Microsoft C++ Build Tools；Rust/前端双栈维护 | 当前电脑缺少 Rust、Cargo、C++ 工具，需新增大型环境 |
| Electron 43 | Windows/macOS 共用代码；React、打包和 AI 辅助生态成熟；SQLite 与系统文件能力直接 | 安装包和内存占用大于 Tauri；需持续更新 Chromium | 当前已有 Node.js 24，实际开发、启动与打包路径最短 |
| Flutter Desktop | 原生渲染一致、跨平台 UI 完整 | 需 Flutter SDK、Dart 和 Visual Studio C++；桌面安装器要额外配置 | 当前电脑缺少 Flutter 和 C++ 工具 |

最终选择 Electron 43.4.1。对1.0而言，“能在当前电脑真实完成、测试和打包”比最小体积更重要。Electron 43 自带 Node 24.18.1 与 Chromium，Windows/macOS 共用 React 界面和绝大部分主进程代码。未来可以迁移到 Tauri，但需要重写系统能力层和 SQLite 调用，UI 可较大程度复用。

## 2. 前端与构建

- React 19 + TypeScript：组件和类型生态成熟，便于长期维护。
- electron-vite 5 + Vite 7：分别构建主进程、CommonJS preload 和 renderer，开发反馈快。没有使用 Electron Forge 的实验性 Vite 插件。
- React Router：使用 HashRouter，打包后的本地文件页面无需服务器路由。
- TanStack Query：统一异步 IPC 查询、缓存失效和保存后的刷新。
- React Hook Form + Zod：表单体验与主进程二次校验共用明确规则。
- Recharts：只实现分类、排行、趋势三种与产品问题直接相关的图表。
- Motion：管理页面进入、导航高亮、弹性弹窗、金额滚动和列表布局补位，并自动响应减少动画偏好。
- 自定义CSS变量 + Lucide操作图标 + Phosphor双色分类图标：不引入大型后台组件库，同时兼顾主题能力和分类视觉层次。

## 3. 本地数据

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| JSON 文件 | 简单、容易查看 | 并发与部分写入风险高；筛选统计、迁移和约束能力弱 |
| IndexedDB | 浏览器原生、无需原生依赖 | 数据位置和人工备份不直观；桌面主进程访问不自然 |
| SQLite | 事务、索引、约束、统计查询和跨平台格式成熟 | 需要 SQLite 绑定和迁移管理 |

最终选择 SQLite + `better-sqlite3` 13。金额以整数分保存，开启外键、WAL、合理同步级别和忙等待；启动执行 `quick_check`。`better-sqlite3` 13 自带 Windows/macOS 的 Node-API 预编译文件，因此设置 `npmRebuild: false`，避免在包含空格的路径下无意义地调用 node-gyp。未来可继续用 SQL 迁移扩展表结构。

## 4. 导入、备份与恢复

- CSV 用于常见表格导入/导出：读取中文表头、逐行校验、稳定指纹查重，并在导入前自动备份。它不作为含退款关联等关系的无损恢复格式。
- 完整备份使用版本化 JSON，第4版包含账目、自定义分类、设置、预算和模板，并对规范化数据计算 SHA-256。
- 恢复前校验结构、金额、日期、分类关系、重复编号和校验值。
- 正式替换前自动保存当前数据，使用单个 SQLite 事务完成替换，错误自动回滚。
- 不采用“合并恢复”，因为没有账号或设备身份时无法可靠判断重复账目。

## 5. 安全边界

- renderer 启用沙箱、上下文隔离和 Web 安全，关闭 Node 集成。
- preload 只暴露类型化的最小 API；主进程验证 IPC 来源和所有参数。
- 只加载打包内本地资源，设置 CSP，拒绝权限请求、外部导航和新窗口。
- 数据库损坏时进入保护状态，不自动删除、重命名或重建原数据库。

## 6. 打包

使用 electron-builder 26：Windows 生成 x64 NSIS 安装包、便携版和解压目录；macOS 配置 DMG/ZIP，并需在 Mac 上分别构建 arm64/x64。当前没有购买签名证书，也不使用开发者账号，因此产物未签名；这不会影响功能，但系统可能显示安全警告。

## Android 1.0 最终技术决策

- 最终采用 Kotlin + Jetpack Compose，不制作 iOS，也不继续用 Electron 充当手机 App。
- Android 数据层采用平台 SQLiteOpenHelper，而不是早期规划中的 Room；理由是当前模型小、迁移与事务边界清楚，能够减少额外代码生成，同时仍保留外键、WAL、索引、quick_check 和版本迁移。
- 设置与账目统一通过 Repository 暴露；轻量偏好使用 Android 本地偏好保存。UI 不直接操作数据库。
- Liquid Glass 最终运行依赖为 Kyant Backdrop 2.0.0，Apache-2.0。Haze 仅属于 0.2/0.3 历史试验，不在 1.0 最终依赖中。
- `QmDeve/AndroidLiquidGlassView` 只用于研究 Refraction、Dispersion、Touch、Elastic 和缓存，没有复制或链接其代码。
- 实时 Backdrop 只用于底栏和少量重点表面；大型快速记账 Sheet 使用统一兼容材质，防止全屏 Blur 在拖动中反复计算。
- 连续底栏共用一块 Lens；点击“记账”属于打开模态面板，不切换页面目的地。面板打开后暂停被完全遮挡的底栏绘制。
- 金额隐私、Liquid Glass、音效、触觉和减少动效彼此独立并永久保存。声音关闭不影响触觉。
- 1.0.1（101）建立正式签名基线；当前 Release 为 1.0.3（103），最低 Android 10。APK 继续使用同一项目专用 RSA 4096 密钥签名，因此可安全覆盖升级；密钥不进 Git，必须另行备份。

## Android 1.0.3 定型决策

- 首页本月趋势采用“本月 1 日至今天”的连续自然日序列，缺少账单的日期补零，避免把本月趋势误画成最近七天。
- 底部导航只等待 Android 正常触摸阈值，不要求长按；拖动时页面和 Lens 由同一状态同步，经过中央记账入口不会误弹。
- 中央记账入口仍属于同一块连续底栏，通过尺寸、颜色和高光提高约一个层级，不叠加独立悬浮球。
- 分类数据库升级到 v2，只增量补齐稳定标识、图标、颜色、启用状态、排序与父级关系；禁止删除或重建用户旧账本。
- 支出预设补齐为 16 个一级分类，预设分类保留稳定身份；自定义分类允许完整编辑与安全停用。
